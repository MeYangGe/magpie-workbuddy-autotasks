看板

账号列表、任务进度、批量操作、实时步骤、排程与历史都在看板里 —— 在 magpie 窗口内会自动跳进去，这里是独立访问入口。

http://127.0.0.1:4390 打开看板

全部接口无鉴权，靠网络边界保护：守护进程默认只绑 127.0.0.1。 改绑 0.0.0.0 后同网段任何人都能触发任务或导出含凭据文件，不用时请关闭端口转发。

说明

如何启用 / 停用

守护进程跟随 magpie：在插件管理里开启本插件即自动拉起 （写 control.json desired=on），关闭插件即优雅退出 （desired=off）。看板顶栏也有「停止守护进程」按钮（POST /api/shutdown）； 浏览器无法启动本机进程，需要手动拉起时在插件目录执行 node daemon.mjs。

Docker / NAS 部署怎么打开看板

守护进程默认只绑 127.0.0.1；容器里需要对外时用选项 listenAddress 或 --addr 绑 0.0.0.0。 此时看板仅容器网桥/局域网可达，请用 SSH 隧道或局域网地址访问，切勿发布到公网 （0.0.0.0 是监听值，不是可打开的地址）。

查容器 IP：docker inspect -f "{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}" magpie； 建隧道：ssh -L <port>:<容器IP>:<port> <user>@<NAS地址>， 映射后仍可用 http://127.0.0.1:<port>/ 打开。实际端口与绑定 host 由守护进程写在 state/daemon.json；看板页面不再显示访问地址，需要时直接看该文件里的 host 与 port。

为什么还停在这张卡（以及窗口内会自动跳走）

本插件声明了 magpie.page.service，magpie 会把 _magpie/service/ 反代到守护进程的 :4390。embed.js 在 magpie.ready 后拿到这个地址就自导航进看板，看板的 /api/* 全走同一前缀，所以窗口里看到的是完整实时界面（含 SSE）。

还停在这张卡，说明 magpie.service 为空：桌面窗口、magpie 版本不支持 page.service，或页面未在宿主内加载。此时本卡只能展示——它跑在 sandbox="allow-scripts" 的 iframe 里、CSP connect-src 'none'、 frame-src 'none'，不允许 fetch / WebSocket，也不嵌套任何外部页面， 因此拿不到 /api/state 与 SSE。请用上面的地址打开独立看板。

想确认是不是跳转失败：按 F12 看 console 里 [workbuddy-tasks] embed: 开头的日志。

看板里能做什么

勾选账号 →「批量接任务」（只接取，不点亮；只提交守护进程判定 canAccept 的任务）、 「批量做任务」（接取 → 点亮 → 领奖完整流水线）、「只领奖」（补领「待领奖」）、 「每日签到」（连登）；自动 / 手动领奖两种模式；每个账号可单独开关「参与任务」。 单账号任务表可逐项接取 / 领奖，并按后端下发的判断字段标注「需在桌面端完成」「无法自动化」 与钉死的专家 id；风控冷却名单直接显示解除时间；实时步骤与滚动日志走 SSE， 断线自动回退轮询；小时窗口排程可编辑并预览下一次运行；历史失败 / 跳过都会留一行说明。

账号导入 / 导出：导出为 hub 同款 workbuddy-accounts JSON （默认含凭据，可改脱敏）；导入走「先预览（只读、不写盘）→ 确认写入 plugin-auth.json（写前自动备份）」两段式，只同步国内版、智能合并， 不删除任何现有账号。
